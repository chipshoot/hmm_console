# Video in Notes — Stage 2 (video on one device) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a video from the photo library to a note at original quality, show it inline with a poster frame, play it full screen with Apple's player, and offer Save to Photos, Share and Remove. All of this works on one device; the video file does not sync yet.

**Architecture:**
- **Record:** a new top-level `videos` key in `NoteAttachments` holds `VideoAttachment` entries: the video `VaultRef`, an optional poster `VaultRef`, and duration, width and height.
- **Inline marker:** the markdown places a video with an ordinary inline image whose URI is the poster's vault path. An older or plain renderer then shows the poster as a photo and never loads the video. This build looks the path up in `videos` and draws a video tile instead.
- **Files:** they move by path, never through memory. A new `IVaultFileStore` imports a file into the vault by moving or copying it on disk and hands back its local path.
- **Native code:** a small iOS plugin (`hmm/video`) probes length and size, writes the poster, presents `AVPlayerViewController`, and saves to Photos.
- **Sync:** the OneDrive byte sync skips video paths; posters sync like photos.

**Tech Stack:** Flutter, Riverpod 3, Drift, `image_picker` (`pickVideo`), `share_plus`, `open_filex`, Swift (AVFoundation, AVKit, Photos). No new pub packages.

**Spec:** `docs/superpowers/specs/2026-11-12-note-video-design.md` (§3 "Attached videos", §5.1, §5.3, §5.4, §8 Stage 2). Stages 0 and 1 are merged to main (91a6f49).

**Branch:** `feat/note-video-stage2` from main.

## Global Constraints

- **Original quality, never re-encoded.** Use `ImagePicker().pickVideo(source: ImageSource.gallery)`. On iOS 14+ this uses PHPicker with `PHPickerConfigurationAssetRepresentationModeCurrent` and copies the file representation (checked in `image_picker_ios` 0.8.13+6). Do not pass `maxDuration` and do not use `pickMedia`.
- **No whole video in memory, ever.** No `readAsBytes`, `getBytes` or `putBytes` on a video file. Use only file moves and copies, file paths, and the native plugin. Posters (small JPEGs) may use bytes.
- **Size limits:**
  - `kVideoWarnBytes = 500 * 1024 * 1024`: above it, a "Large video" dialog with Cancel/Add.
  - `kVideoMaxBytes = 2 * 1024 * 1024 * 1024`: above it, the video is refused.
  - `kMaxAttachmentBytes` (8 MB) stays for every non-video attachment.
- **Video content types:** `video/quicktime` (`.mov`), `video/mp4` (`.mp4`), `video/x-m4v` (`.m4v`). Anything else is refused.
- **Vault paths:** video at `attachments/note-<id>/<uuid>.<ext>`, poster at `attachments/note-<id>/<uuid>.jpg` (same uuid). Videos are never sensitive and never encrypted.
- **Inline marker:** `![Video](hmm-attachment://<poster path>)`. If no poster could be made, use the video path. The alt text is the fixed English word `Video`, because it is stored data and is not localized. A pending pick uses `hmm-attachment://pending/<uuid>`, like images.
- **Never nest a new vault path inside an existing entry kind.** Videos live under the new `videos` key, and every vault path in a video entry is added to `NoteAttachments.vaultPaths`, for known and preserved entries alike.
- **Mode and sensitivity gates:**
  - In `cloudApi` mode the video button looks greyed out; tapping it says "Videos need OneDrive sync for now".
  - A note holding any sensitive attachment (saved or pending) refuses videos with "Videos can't be added to notes with sensitive items yet".
  - There is no "sensitive video" option.
- **Nothing autoplays.** Playback starts only from a tap, which presents the full-screen player already playing.
- **Project rules:**
  - Icon buttons are `HmmIconButton` with a localized tooltip and Apple glyphs via `adaptiveIcon`.
  - Every new string goes in both `app_en.arb` and `app_zh.arb`, with the gen files regenerated by `flutter gen-l10n` and committed.
  - New controls get help entries.
  - Never `ref.watch` inside a `LayoutBuilder` builder.
  - Never run `dart format` on a directory.
  - Actions that hide data use `showUndoableAction`.
- **Rollout:** install this build on both iPhone and iPad (back up first, install over) before any note gets a video. Stage-1 builds keep a `videos` key intact, but their Settings "clean up storage" sweep does not count its files as in use.

JSON shape of one entry:
```json
{"video": {"kind":"vault","path":"attachments/note-5/u1.mov","contentType":"video/quicktime","byteSize":123,"originalName":"IMG_1.MOV"},
```

- Unknown keys are kept in `extra` and written back by `toJson`.

### Task 3: Import files into the vault by path

**Files:**
- Create: `lib/core/data/vault/vault_file_store.dart`
- Modify: `lib/core/data/vault/local_vault_store.dart`, `lib/core/data/attachments/attachment_providers.dart`
- Test: `test/core/data/vault/local_vault_file_store_test.dart`

**Interfaces:**
- Produces: `abstract interface class IVaultFileStore` with:
  - `Future<void> importFile(String relativePath, File source)`: moves `source` into the vault at `relativePath`. It throws `ArgumentError` for an invalid path or a sensitive path (`isSensitiveVaultPath`), and `VaultStoreException` if `source` is missing.
  - `Future<File?> localFile(String relativePath)`: the absolute file, or null when it is not on this device.
- Produces: `LocalVaultStore implements IVaultStore, IVaultFileStore`.
- Produces: `final vaultFileStoreProvider = FutureProvider<IVaultFileStore?>`. It returns null in `cloudApi`. Otherwise it returns `await ref.watch(baseVaultStoreProvider.future)` when that store is an `IVaultFileStore`, else null. It uses the raw store, never the encrypting decorator; videos are never sensitive.

This is a separate interface, not new methods on `IVaultStore`, so the 14 test fakes of `IVaultStore` stay unchanged.

`importFile` algorithm (atomic; never reads the file into Dart memory):
1. Validate the path and create the parent directory.
2. Try `source.rename(target.path)`.
3. If that throws a `FileSystemException` (a different volume): `source.copy('${target.path}.tmp')`, then rename the `.tmp` to the target, then delete `source`. On failure, delete the `.tmp` and rethrow.

  - `localFile returns the file or null`: after an import, `localFile(...)!.lengthSync() == 3`; a path that was never written gives null.
  - `refuses invalid and sensitive paths`: `../x.mov` throws `ArgumentError`; `buildSensitiveAttachmentPath(noteId: 1, ext: 'mov')` throws `ArgumentError`.
  - `missing source throws VaultStoreException`.

**Interfaces:**
- Produces, in `video_platform.dart`:
  - `class VideoProbe { const VideoProbe({this.durationMs, this.width, this.height, this.posterWritten = false}); … }`
  - `abstract interface class VideoPlatform`, with three methods:
    - `Future<VideoProbe> probe(String videoPath, {required String posterPath})`
    - `Future<void> play(String videoPath)`
    - `Future<bool> saveToPhotos(String videoPath)`, where false means Photos permission was denied
  - `class MethodChannelVideoPlatform implements VideoPlatform`, using `MethodChannel('hmm/video')`.
  - `class FallbackVideoPlatform implements VideoPlatform`, for non-iOS: `probe` returns `const VideoProbe()`, `play` calls `OpenFilex.open(videoPath)`, and `saveToPhotos` returns false.
  - `final videoPlatformProvider = Provider<VideoPlatform>`, which picks `MethodChannelVideoPlatform` on iOS and the fallback elsewhere.

Channel contract:

| Method | Arguments | Returns |
|---|---|---|
| `probe` | `{path, posterPath}` | `{durationMs:int?, width:int?, height:int?, posterWritten:bool}` |
| `play` | `{path}` | null once the player is presented |
| `saveToPhotos` | `{path}` | `bool` |

What `VideoPlugin.swift` does:
- `probe`, off the main thread: `AVURLAsset`.
  - Duration in milliseconds.
  - Size from the first video track's `naturalSize` with `preferredTransform` applied (absolute values, so portrait reads as portrait).
  - Poster from `AVAssetImageGenerator` with `appliesPreferredTrackTransform = true` and `maximumSize = 1280×1280`, at `min(1 s, duration/2)`, written as JPEG at quality 0.8 to `posterPath`.
  - Any poster failure gives `posterWritten: false`, not an error.
- `play`:
  - Set `AVAudioSession` to category `.playback`.
  - Present `AVPlayerViewController` with `modalPresentationStyle = .fullScreen` from the top view controller.
  - Call `player.play()` once it is presented.
- `saveToPhotos`:
  - Call `PHPhotoLibrary.requestAuthorization(for: .addOnly)`.
  - If authorized or limited, run `performChanges` with `PHAssetCreationRequest.creationRequestForAssetFromVideo(atFileURL:)` and return true; if denied, return false.
  - A failed change returns `FlutterError(code: "save_failed")`.

Keep the Swift file as thin as `DocumentScannerPlugin.swift`: no rules, only the platform calls.
